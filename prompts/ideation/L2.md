
### Level 2 (Synthesis): The Batch Editor

You have successfully completed L1. You now have a pool of, say, 8 draft points sitting in your database for `01_tata-neu.md`. Some are great, some are weak, and a couple probably overlap because you mentioned similar tasks in different stories.

Level 2 is where the AI stops acting like a data extractor and starts acting like an **Editor-in-Chief**. It looks at the entire batch of L1 points for a single company and synthesizes them into a cohesive narrative.

Here is how the "Deterministic + Semantic" approach works for merging, splitting, and dropping.

#### 1. The Semantic Layer (Vector Math)

Before calling the LLM, you use code to find redundancies.

- Remember those embeddings we generated in L1? You take the vectors for all 8 points and run a cosine similarity matrix using `numpy`.
    
- If Point 2 and Point 5 have a similarity score of `> 0.85`, your code flags them as a "Merge Candidate Pair."
    
- **Why this is powerful:** You didn't waste LLM tokens asking "are any of these similar?" You used cheap, instantaneous math to find the overlaps, even if they use completely different words.
    

#### 2. The Deterministic Layer (Rules & LLM Execution)

Now you build the prompt for the **Batch Editor LLM**. You feed it the full list of 8 points, but you explicitly pass it the math you just did: _"Points 2 and 5 have been mathematically flagged as highly redundant. Point 7 has an L1 Impact Score of 2/10."_

You force the LLM via `instructor` to output a structured editorial plan:

Python

```
class PointAction(BaseModel):
    action: Literal["keep", "merge", "split", "drop"]
    target_l1_ids: List[str] # Which points are affected
    editorial_reasoning: str # E.g., "Merging 2 and 5 because both describe the payment API, combining the 15% metric with the 'Architected' verb."
    new_cv_point: Optional[CVPointCandidate] # The newly generated L2 point, if applicable
```

By feeding the LLM the semantic math and the L1 Judge scores, you constrain its hallucination space. It doesn't have to guess what's bad or redundant; it just executes the editorial action you guided it toward.

### 1. Hard-Coded Token & Text Cleaners

Run this string sanitization function over any generated `rendered_bullet` before saving it to the SQLite database or exporting to RenderCV YAML to ensure old parsers don't break on encoding:

```
import re

def sanitize_for_machine_parsers(text: str) -> str:
    # 1. Convert smart/curly quotes to straight ASCII quotes
    text = text.replace("“", '"').replace("”", '"')
    text = text.replace("‘", "'").replace("’", "'")
    
    # 2. Normalize em-dashes and en-dashes to a standard hyphen
    text = text.replace("—", "-").replace("–", "-")
    
    # 3. Force fancy bullets or directional arrows into standard hyphens or clean unicode circles
    text = re.sub(r"[→|✓|✔|►|•]", "-", text)
    
    return text
```

```
def check_keyword_density(full_resume_text: str, keyword: str) -> dict:
    # Case-insensitive count of the exact keyword boundary
    count = len(re.findall(r'\b' + re.escape(keyword) + r'\b', full_resume_text, re.IGNORECASE))
    
    if count < 25:
        status = "LOW"  # Progress bar indicator: Needs more integration
    elif 25 <= count <= 35:
        status = "OPTIMAL"  # Progress bar indicator: Green sweet spot
    else:
        status = "STUFFED"  # Progress bar indicator: Red flag for keyword stuffing
        
    return {"count": count, "status": status}
```



### Level 2 (QA): The L2 Judge

What does the L2 Judge do? **Exactly the same thing as the L1 Judge.** You literally just re-use the function.

- **Why we need it:** When the Batch Editor merges Point 2 and Point 5 into a brand new L2 Point, the old L1 Judge scores are obsolete. You need to grade the new, mutated point so it has accurate metadata in the database.
    
- **How to use it:** Once the Batch Editor outputs its final list of L2 points, you run a simple `for` loop, passing each new point to the Judge prompt to get its final `impact_score`, `ats_score`, and `completeness_score`. This establishes the final hierarchy for when your Customizer engine searches the database later.
